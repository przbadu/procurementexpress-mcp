**Step 2: Create src/tools/policies.ts**

Create a new file with `registerPolicyTools(server, apiClient)` function containing 6 tools:

1. **list_policies** (POL-01) — `GET /policies` with query params: status, archived, scope, category, budget_id, search, page. Returns `{ policies: PolicySummary[], meta: PaginationMeta }`. Use URLSearchParams to build query string. All params optional.

2. **get_policy** (POL-02) — `GET /policies/:id`. Returns `{ policy: PolicyDetail, versions: PolicyVersion[] }`. Input: `id` (number, required).

3. **create_policy** (POL-03) — `POST /policies`. Body: `{ policy: { name, description?, status?, scope?, category?, content?, min_amount?, max_amount?, min_quotes_required?, archived?, budget_ids?:number[], required_attachments?:string[] } }`. Name is required, all others optional. Returns PolicyDetail.

4. **update_policy** (POL-04) — `PATCH /policies/:id`. Same body shape as create (all optional). Returns PolicyDetail.

5. **delete_policy** (POL-05) — `DELETE /policies/:id`. Returns textResponse with success message. Input: `id` (number, required).

6. **list_policy_templates** (POL-06) — `GET /policy_templates`. No params. Returns `{ templates: PolicyTemplate[] }`.

Follow the established pattern from budgets.ts:
- Import `z` from "zod", types from "../types.js", helpers from "../tool-helpers.js", ApiClient from "../api-client.js"
- Export type `Server` from tool-helpers
- Wrap every handler with `withErrorHandling()`
- Use `apiClient.buildPath("/policies")` and `apiClient.buildPath("/policy_templates")` -- never hardcode version
- Use `jsonResponse()` for data, `textResponse()` for delete confirmation

Note on `scope` field: The JSON key is `scope` (not `policy_scope`). The Rails serializer aliases `policy_scope` to `scope` in JSON output. Use `scope` as both the Zod input field name and the body key.

Tool descriptions should mention the feature flag: "Requires policies feature to be enabled for the company."
